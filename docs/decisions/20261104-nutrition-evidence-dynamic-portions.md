# #21：營養證據與本餐動態份量

日期：2026-11-04。狀態：本機候選；尚未發布或實機驗收。

## 問題與決定

99 項官方基準已獲實機驗收，且採用流程核對完整檔案 SHA-256。直接將來源欄位加入母庫會破壞已驗收的基準採用／照片保留流程，因此保持 `ingredients.json`、`dishes.json` 的原始位元組不變。

`OfficialNutritionEvidence.js` 是執行時來源索引；以 ID、名稱、品牌、營養／重量快照對應母庫。沿用 2026-10-28 的 89 項逐項稽核，不重認證歷史數字；新增 10 項逐項列為待確認。最新盤點在 `docs/audits/nutrition-2026-11-04.json`，共 37 項官方資料庫估算、1 項歷史本人確認標示、61 項待確認。維力蒸煮麵保留 65g／包與既有數值，但通路核對不等於本人持有包裝核實，故列待確認。來源未確認不表示數值錯誤。

產品標示沿用 Gemini Vision OCR。無法辨識的值為 null；同質量／容量單位才可推算每份與每百單位。保存前可逐欄核對品牌、規格、重量基準、五項營養與每顆可食重量；核對後產生身分／營養快照與日期。改動身分、營養、重量會失效。缺資料可保存為待確認；正份量不可納入精算或錄餐。蝦仁漿、王子麵與五項計數缺口維持原數值／引用，不採另一品牌數字、不猜重量。已補可編輯品牌與鈉欄位。

料理 defaultIngredients 的數值僅作配方組成／比例與手動起點。舊 memberPortions 原樣保留，但不自動當作目前建議；新增食材不再寫永久個人份量。計數新增仍預設 1，其他新項目從 0 開始交由本餐建議或手動填寫。舊份量記憶只透過明確「手動帶入舊份量／份量記憶」操作套用，錄餐不回寫配方。

AI 每次讀目前核對的體重／測量日期、健康與體重目標、每日五項目標、限制／禁用食材、當日已攝取、餐次、全部食材、實際人數與剩餘餐數；不再套固定人設、Jason 倍率或 2,200 kcal 特例。標準模式以剩餘額度除以本人填寫的剩餘餐數；剩餘模式使用全部剩餘額度。原有每日目標只作待核對的欄位起點，不宣稱仍是有效健康處方；不自動由體重推斷新的健康目標。

身體資料／目標說明／限制只存在本次畫面記憶體，不進 Git、Issue、Personal Kitchen State 或同步服務；畫面清楚告知點擊計算將本餐資料送至 Gemini。程式沿用既有引擎重算 AI 營養、驗單位、範圍與禁用 ID，拒絕超出本餐熱量／碳水／脂肪／鈉預算。蛋白質是目標，不強迫在其他額度不足時超額。自由文字限制仍須本人核對，機械禁用守門以明確禁用 ID 為準。無來源、無確認資料、無金鑰、AI 超時或驗證失敗，都保留配方／手動份量，不宣稱已完成動態建議。

## 儲存影響、相容與回復

- 沒有 Supabase schema、RLS、Storage、Personal Kitchen State、Scope 成員或同步合併政策變更；未執行正式資料操作。
- 營養證據是裝置 custom ingredient 的加法欄位；不自動升格官方、不跨裝置或 Scope 搬移。舊自訂食材保留值，但無來源證據時阻擋正份量精算。
- 舊 dishes／memberPortions／份量記憶／飲食紀錄及引用保留；不批次遷移或清除。官方母庫兩檔與已驗收照片流程不變。
- 計算畫面 sessionStorage 改用 `family_kitchen_calc_session_state:<scope>`（household、ariel、signed-out），並驗證內部 scopeId；舊無 Scope 的共用暫存不讀、不刪、不搬移。不同 Scope 不共用本餐畫面暫存。
- 新增 `kitchen_v2_nutrition_edit_backup` 保存每次編輯前兩個食材 cache 的內容。沿用照片備份工具將舊 Base64 保存在裝置 IndexedDB，備份 JSON 不寫 Base64。備份／配額失敗或備份期間 cache 改變時，停止該次儲存。此為裝置共用食材備份，不是 Personal Kitchen Scope 備份。
- 程式回復：經發布授權後可用一般 revert 回復本候選並重部署，不 force push。資料回復須先保留目前 cache，再人工核對上述營養編輯備份；不是用 Git revert 還原正式家庭資料。未設計自動跨 Scope restore。
- PWA 直接受影響的 import chain 更新到 main／index；Auth 與同步 singleton 的無版本 URL 不變。

## 驗證與待人類事項

隔離測試包含三類來源、99 項索引／89 項稽核重用、數值／身分／重量失效、null／0 區分、計數／g／ml、目標與當日攝取變動、額度／禁用／AI 結構拒絕、手動份量／明確歷史帶入、Scope 暫存、備份失敗不變更資料。既有營養稽核／單位測試繼續驗歷史數值與換算；另以真實引擎來源套件驗生產守門，未將舊測試的算術通過當成營養值核實。

本機瀏覽器以假資料檢查目標確認、禁用勾選、表單品牌／五項營養及計數重量欄位，窄畫面沒有橫向捲動。不是 iPhone Safari／主畫面 PWA 或實際 Gemini／Supabase 端到端證據。

仍需本人提供／核對實際商品標示與單顆重量才能解開待確認食材；自由文字醫療／飲食限制不能由本次測試認證。發布需另獲明確授權，發布後集中驗收 iPhone 的 OCR 核實、動態目標、手動修改、重開快取與舊照片保留。
