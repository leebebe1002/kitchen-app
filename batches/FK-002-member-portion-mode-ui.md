# Batch：FK-002 成員個別份量模式 UI

## Goal

在料理營養計算機中實現就餐成員個別份量模式（標準份量 vs 剩餘額度），支援「餐別＋當日飲食紀錄」智慧預判、膠囊長按左右展開模式選項、獨立顯示目前模式，並無縫整合至備料營養計算提示詞。

## Why

多人共餐時，不同成員當日的飲食進度不同（例如 Bebe 晚餐需嚴格配平剩餘額度，Jason 與樂樂則需要充足標準份量）。目前計算機僅支援全域切換，無法滿足個別化營養配平需求。

## Scope

- 讀取當前時段（`currentSlot`）與當日飲食紀錄（`engine.getDailyLog`），依預判規則自動初始化每位成員的份量模式。
- 成員膠囊互動升級：
  - 未選取：點一下加入這餐。
  - 已選取：點一下取消這餐。
  - 已選取：長按從該膠囊左右展開選項（左：標準、右：剩餘）。
  - 選擇模式後收合並在膠囊旁顯示目前模式標籤。
  - 一次僅允許展開一位成員，長按不誤觸點擊。
  - 首次使用顯示淡提示：「長按可調整份量模式」（可關閉並持久化）。
- 料理計算（`calculate`）邏輯整合：
  - 根據各就餐成員的模式動態組裝 AI Prompt 剩餘額度指令（僅對設定為「剩餘額度」的成員進行額度配平壓控）。
- 更新必要載入鏈之 Version Tag（`CalculatorView.js`、`style.css`、`main.js`、`index.html`）。
- **不在本 Batch 內**：
  - 不修改共用食材母庫、Personal Kitchen State 與 Supabase 資料表 schema。
  - 不更動 TrackerView 或其他非計算機頁面的核心邏輯。

## Must Not Break

- 既有單一成員／多人選取功能必須正常運作。
- 就餐成員勾選狀態與食材份量關聯不得損壞。
- 本地計算機狀態暫存（`sessionStorage`）相容性。
- iOS Safari PWA 觸控體驗（不可觸發系統文字選取、callout 或造成頁面滾動卡頓）。
- 保持 CLI-first 操作原則，未獲確認前不 commit、不 push、不 merge。

## Done When

1. 進入計算機時，各成員份量模式依「早餐預設標準、中餐預設標準、晚餐有紀錄預設剩餘／無紀錄預設標準」正確預判。
2. 點擊未選取成員正常加入；點擊已選取成員正常取消。
3. 長按已選取成員膠囊約 450~500ms 觸發左右展開（左：標準、右：剩餘），放開不會誤觸點擊。
4. 點選模式後左右選項收合，膠囊旁顯示對應模式標籤（如「標準」或「剩餘」）。
5. 同一時間最多僅一位成員展開，點選外部或另一位成員時自動收合前一個。
6. 首次進入顯示淡提示，關閉後不再出現。
7. 送出計算時，AI Prompt 精準按成員區分標準與剩餘額度需求。
8. 相關 Version Tag 正確更新，iOS Safari 正常載入。
